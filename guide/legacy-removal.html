Legacy removal ​

Implements: REL-06 · see CHARTER.md Part 8 and SEMVER.md. Checked by: tests/tdd/scripts/legacy-removal.test.ts.

13.0.0 removes the legacy construction tree. From then on createEsi() from @lgriffin/esi.ts/client is the only way to call ESI: one runtime, esi.public for the operations that need no scope and esi.as(identity) for the rest, over the operations generated from the vendored OpenAPI document (MULTI-CHARACTER.md).

SEMVER.md requires a minor release to mark a surface @deprecated before a major release removes it. 12.1.0 is that release for everything in the table below. Each name carries a @deprecated JSDoc tag that names createEsi(), so editors strike it through and TypeDoc flags it. Nothing logs a warning at runtime, and nothing changes behaviour before 13.0.0.

This page is the manifest. It lists every surface 13.0.0 takes away, what replaces it, and the capabilities createEsi() does not offer yet. A test reads the table and fails if any name in it is missing from the API report (etc/esi.ts.api.md) or is not marked @deprecated there.

The pipeline rows from ApiClient to CircuitBreakerStats are root names only. createEsi() and the request pipeline still use the declarations behind them, so the root entry exports deprecated aliases (src/legacyExports.ts) instead of tagging the declarations, and the API report shows each as an alias of an unexported …_2 symbol. 13.0.0 removes the names from the root entry; the internals stay.

The schemas carry no tag. A tag on each of the 225 would flag the endpoint maps, the response types and every schema test instead of consumers' uses, and aliasing the root schemas namespace to tag it would drop every schema from the API report, which is how a tightened schema is caught as a break (SEMVER.md). The branded ID types and brand in src/types/branded.ts are not response types and are not deprecated; src/auth uses CharacterId.

Internal modules go with them and need no deprecation, since no entry point exports them: src/clients/ClientRegistry.ts (createClientInstance, ClientInstance, marked @deprecated anyway), the 39 endpoint maps in src/core/endpoints/*Endpoints.ts and createClient().

The scope-tree paths in the table are the generated ones in src/generated/operations.generated.ts; an editor completes the rest of each path. Every one of the 235 routes in the legacy endpoint maps has a generated operation except the two in gap G4. The beta routes (SKINR and the rest of Paragon Hub, military campaigns, freelance jobs, corporation projects) are all in the vendored spec and generated.

Not decided yet ​

These root exports are not deprecated in 12.1.0. If 13.0.0 is to remove any of them, a 12.x minor release has to deprecate it first, so decide before the last 12.x release:

  • TokenProvider and FetchLike from src/core/ApiClient.ts: EsiClientConfig.onTokenRefresh and ApiClientBuilder.setFetch take them. ./client has its own TokenProvider port and HttpTransport;
  • the branded ID types and brand (src/types/branded.ts) and the EsiSpec namespace of generated spec types.

EsiDatasource stays: EsiOptions uses it.

Lint while the tree is deprecated ​

sonarjs/deprecation reports every use of a deprecated declaration. eslint.config.mjs turns it off only where the deprecated surfaces refer to one another or are under test, each with its reason in the config:

  • in src/ and scripts/: the construction tree (src/EsiClient.ts, src/EsiClientBuilder.ts, src/clients/, src/core/ApiClientBuilder.ts), the response types (src/types/*.ts and src/types/generated/spec-alignment.check.ts), src/core/endpoints/createClient.ts, src/testing/TestDataFactory.ts, src/auth/EsiTokenManager.ts and scripts/quality/live-health.ts (G17). A new use anywhere else is still an error;
  • in tests/: the 135 files in config/eslint/legacy-tests.cjs, which test the deprecated surfaces. Everywhere else in tests/ it stays a warning held by npm run lint:ratchet, so a new use of a deprecated API is still caught. A file leaves the list when it moves to createEsi(), and 13.0.0 deletes the list with the files.
